# In-browser replays with Pyodide: design

Date: 2026-10-15. Status: approved in conversation, pending review of this document.

## Goal

Watch any match on the website by running the real Papersseum engine in the
visitor's browser. A replay file is only `seed + action log`; the browser
re-runs the match with Pyodide, draws it, and checks that the result it gets
matches the recorded one. This settles the "Replay viewer for ladder matches"
item left open in `2026-10-13-web-app-design.md` in favour of Pyodide.

Two entry points:

- `/matches/[id]`: replays a finished ladder match from its stored replay.
- `/replay`: replays a `.jsonl` / `.jsonl.gz` file the visitor drops in or picks.
  The file never leaves the browser.

Having the engine itself in the browser (not pre-rendered frames) is the point:
it is what makes dropped files and result checking possible, and leaves the
door open for later in-browser features.

## Decisions from the owner

- Pyodide runs the engine. Not worker-saved frames, not a TypeScript port.
- Only the current engine is shipped. A replay whose `engine_hash` differs from
  the shipped engine still plays, and is labelled as recorded on an older
  engine that can't be verified. No archive of past engine builds.
- The engine package is a wheel generated by a script and committed under
  `web/public/engine/`, like `home-replay.dat`. A library test fails when the
  committed wheel differs from the `papersseum/` source. (The web build and its
  CI job have Node only; this keeps Python out of `next build`.)
- Pyodide runs in a Web Worker and streams frames, so playback starts before
  the whole match is computed.
- The visual rules of the web app still hold: no badges, pills or decorative
  icons. The verification result is a line of plain text.

## Components

### `papersseum/frames.py` (new, in the library)

The one encoder for viewer frames, shared by the browser and
`web/scripts/make_replay.py`. Cell bytes and frame records are exactly the
`PSRP` v1 layout already documented in `make_replay.py` and read by
`web/lib/replay-format.ts`.

```python
class FrameEncoder:
    def __init__(self, seed, action_log): ...
    def header(self) -> bytes        # b"PSRP", version, H, W, frames, players,
                                     # initial cells, frame 0 heads
    def next_batch(self, n=50) -> bytes | None
                                     # next <= n frame records (heads, u16 count,
                                     # diffs); None when finished
    def result(self) -> dict         # {"scores", "placements"} once finished

def encode_frames(seed, action_log, batch=50):
    """Yield header() then every batch. Concatenated, this is the PSRP body."""

def check_replay(rep) -> None:
    """Raise ValueError with a plain-English reason unless: seed is an int,
    action_log has 1..TOTAL_TICKS/STEP_PER_DECISION rows (1,800), and every
    row is N_PLAYERS (5) actions in {0, 1, 2}."""
```

- `frames` in the header is `len(action_log) + 1` (the engine only ends at
  the final tick, so a valid log never stops early). The encoder asserts this.
- It drives `Engine` directly like `iter_frames` (no observations) and diffs
  consecutive cell arrays with numpy, as `make_replay.py` does today.
- `make_replay.py` becomes a thin wrapper:
  `gzip.compress(b"".join(encode_frames(...)), compresslevel=9, mtime=0)`, and
  must still produce today's `home-replay.dat` byte for byte.
- Exported from the package as `papersseum.frames`; the engine modules and
  therefore `ENGINE_HASH` are unchanged.

### `web/scripts/build_engine.py` (new)

Run from the repo root: `uv run --frozen python web/scripts/build_engine.py`.

- `uv build --wheel --package papersseum` into a temp dir.
- Removes old wheels from `web/public/engine/`, copies the new
  `papersseum-<version>-py3-none-any.whl` in.
- Writes `web/public/engine/manifest.json`:
  `{"wheel": "<filename>", "engine_hash": "<ENGINE_HASH>", "version": "<__version__>"}`.

Rerun whenever anything under `papersseum/` changes.

### Library test `tests/test_web_engine.py` (new)

- Reads `web/public/engine/manifest.json`, opens the wheel it names, and asserts
  every `papersseum/**/*.py` in the wheel equals the file in the repo and that
  the sets of files are the same. Fails with "run web/scripts/build_engine.py".
- Asserts `manifest.engine_hash == papersseum.ENGINE_HASH`.

### `web/public/engine/worker.mjs` (new)

> **Note (2026-10-15):** the worker and its Pyodide runtime live in `web/public/engine/worker.mjs` and `web/public/engine/runtime.mjs` (not `web/workers/engine.worker.ts` / `web/lib/engine-runtime.ts`), as unbundled plain ES modules: Pyodide 314 requires a module worker, and Turbopack's worker bootstrap is classic-only (`importScripts`). The page starts it with `new Worker("/engine/worker.mjs", { type: "module" })`.

A module Web Worker.

- Loads Pyodide from jsDelivr at one exact pinned version (a constant in the
  file; latest stable at implementation time), then `loadPackage(["numpy",
  "micropip"])`, then `micropip.install` of `/engine/<manifest.wheel>`. Loaded
  once per worker and reused for every replay on the page.
- Messages in: `{type: "run", id, bytes}` (raw replay bytes, gzipped or
  plain) and `{type: "cancel", id}`.
- Per run: `loads_replay` → `check_replay` → `FrameEncoder`. Posts:
  - `{type: "status", id, stage: "loading-engine" | "computing"}`
  - `{type: "start", id, header: ArrayBuffer, players, engineHash, recorded}`
    where `players` is the header's player list and `recorded` is the replay's
    `{scores, placements}` or null.
  - `{type: "frames", id, bytes: ArrayBuffer, upTo}` per batch (transferred).
  - `{type: "done", id, scores, placements}`
  - `{type: "error", id, stage: "engine" | "replay", message}`
- Between batches it yields to its event loop, so a `cancel` (or a new `run`)
  is seen and the current run stops pulling batches. Python never runs a whole
  match in one call.
- Replay bytes are only ever parsed as data. Nothing from a replay is executed.

### `web/lib/engine-client.ts` (new)

Owns one lazily created worker per page. `runReplay(bytes, handlers)` returns a
`cancel()`; stale messages (old `id`) are dropped. If the worker fails to
start, Retry creates a fresh one.

### `web/lib/replay-format.ts` (extended)

- `decodeReplay` is split into `decodeHeader(bytes)` and an incremental
  `FrameStore` with `append(bytes)`, `available` (frames decoded so far),
  `frames` (total), and the same `applyFrame` / `headsAt` reads. The full-file
  `decodeReplay` stays, built on the two, so the home page and its tests are
  unchanged.
- `verdict(input)` (pure):
  - `engineHash !== shippedHash` → `{kind: "older-engine"}`
  - no `recorded` and no database seats → `{kind: "unchecked"}`
  - placements equal and every coverage within a relative 1e-5 (`|a - b| <= 1e-5 * max(1, |a|, |b|)`) of both the replay's
    result line and (on the match page) the database seats → `{kind: "verified"}`
  - otherwise `{kind: "mismatch", seats: [...]}` listing the differing slots.
  The tolerance is relative because `match_players.coverage` is `real` (float4), which PostgREST
  returns with about 6 significant digits (relative error up to ~5e-6).

### `web/components/replay-viewer.tsx` (new, client)

Props: `source` (`{url}` or `{bytes}`), optional `expected` (database seats:
slot, name, placement, coverage).

- Canvas board, drawn with the existing `buildColorTable` / `paintCells` and
  theme handling (light/dark from the system setting, live switch).
- Controls, plain buttons: play/pause, a range scrubber, speed 1× / 2× / 4×,
  and a time readout (`1:23 / 3:00`). The scrubber's reachable part is the
  frames computed so far; seeking backwards re-applies diffs from the start
  (cheap at 1,801 frames).
- Autoplays when the first batch arrives, except under
  `prefers-reduced-motion`, where it waits for Play.
- Status line under the board, plain text:
  - "Loading the replay engine (one-time download)…"
  - "Computing the match… 42%"
  - "Verified: the engine reproduced this result." / "Result mismatch: seat 2
    (name) placed 3rd here, 2nd recorded." / "Recorded on an older engine
    (abc123…), so this result can't be verified." / "No recorded result to
    check this replay against."
- Seat legend: swatch + bot name. On the match page names come from
  `expected` (ladder replay headers carry `bot_id` and `submission_id`, not
  names). On `/replay` they come from the header's `bot_name` when present
  (files saved by `papersseum play`), else "Player 1" to "Player 5".
- Errors replace the board with a message and, for engine load failures, a
  Retry button.

The home page `BoardReplay` is not changed.

### Pages

- `/matches/[id]`, status `done` with a `replayPath`: the "viewer isn't built
  yet" box becomes the viewer (`source={{url: replayUrl(...)}}`,
  `expected` from the seat rows), with the Download link kept beneath it.
  Supabase public storage serves the replay with permissive CORS.
- `/replay` (new, public, static shell): one paragraph, a drop zone that is
  also a file picker (`.jsonl`, `.gz`), and the viewer once a file is chosen.
  Files over 1 MB are refused before reading ("That file is too big to be a
  replay; real ones are a few KB."). Dropping another file cancels the current
  run. Linked from the match page ("or open a replay file") and from
  `/getting-started` next to `--save-replay`. Not added to the header.

## Data flow

```
match page / drop page
  └─ bytes ─▶ engine-client ─run─▶ engine.worker (Pyodide + papersseum wheel)
                                    loads_replay → check_replay → FrameEncoder
       ◀─ start(header, recorded) ─┤
       ◀─ frames(batch) × ~36 ─────┤   viewer appends to FrameStore, plays
       ◀─ done(scores, placements) ┘   viewer runs verdict(), shows status line
```

## Error handling

| Case | Shown |
|---|---|
| Pyodide/numpy/wheel fails to load (offline, CDN down, no WebAssembly or Worker) | "Couldn't load the replay engine." + Retry. Match page keeps the Download link |
| Replay fetch fails on the match page | "Couldn't fetch this replay." + Retry |
| Not gzip/JSONL, not a replay header, or `check_replay` rejects it | "This isn't a Papersseum replay: <reason>" |
| File over 1 MB on `/replay` | Refused before reading, message above |
| Replay has no result line | Plays; "No recorded result to check this replay against." |
| `engine_hash` differs from the shipped one | Plays; older-engine line |
| Python raises mid-run | "The replay stopped at 1:23: <message>"; frames so far stay playable |

## Testing

- **pytest (library)**
  - `FrameEncoder` round trip: applying every batch's diffs reproduces
    `iter_frames`' owner, trail and heads for a recorded seed, and `result()`
    equals `replay_match`.
  - `make_replay.py`'s output equals the committed `home-replay.dat` byte for
    byte.
  - `check_replay` rejects: non-int seed, empty log, 1,801 rows, a 4-action
    row, an action of 3.
  - `tests/test_web_engine.py` wheel freshness (above).
- **vitest (web)**: `FrameStore` (append in uneven batches, seek back and
  forth, equals full-file decode), `verdict()` (all four kinds, float4
  tolerance), the `/replay` size guard.
- **Pyodide determinism (`npm run test:pyodide`, added to the Web CI job)**:
  loads the committed wheel in Pyodide under Node (the `pyodide` npm package,
  dev dependency), replays a committed fixture `web/lib/fixtures/match.jsonl.gz`
  (a baseline match recorded natively) and asserts scores and placements equal
  the fixture's result line. This is the guard against Pyodide's numpy
  diverging from the server's.
- **Manual**: a finished ladder match and a dropped local replay, in light and
  dark, at phone width, with reduced motion; a replay edited to a different
  `engine_hash`; a corrupted file; offline (engine load error).

## Costs

- First visit downloads Pyodide and numpy (about 10–15 MB), then the browser
  caches it. The wheel is tens of KB.
- Computing a full match takes about 1.2 s natively; expect roughly 3–5 s in
  Pyodide, overlapped with playback.

## Out of scope

- Archived engine builds for exact replay of old matches.
- Live matches; running agents in the browser; uploading replays.
- Self-hosting Pyodide (swap the CDN URL for `public/` files later if needed).
- Changing the home page board.
